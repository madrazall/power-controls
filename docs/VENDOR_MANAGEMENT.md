# Vendor Management System\n\n## Overview\n\nThe vendor management system maintains digital \"vendor ID cards\" with complete contact information, available materials, pricing history, and previous order references.\n\n## Vendor ID Cards\n\nEach vendor has a complete profile storing:\n\n### Contact Information\n- **Company Name** (required) - \"Digi-Key\", \"Mouser\", \"Local Electronics Supply\"\n- **Contact Person** (optional) - Sales rep or account manager name\n- **Email** (optional) - Primary contact email\n- **Phone** (optional) - Phone number\n- **Address** (optional) - Physical mailing address\n- **Website URL** (optional) - Company website\n\n### Payment Methods\n- Multiple payment options per vendor:\n  - Credit Card (Visa, Mastercard, Amex)\n  - Wire Transfer / Bank Transfer\n  - Check / Money Order\n  - COD (Cash on Delivery)\n  - Purchase Order / Net 30/60/90\n  - PayPal / Digital Payment\n  - Custom (stored as text)\n\n**Example:**\n```json\n{\n  \"vendor_id\": \"V001\",\n  \"company_name\": \"Digi-Key\",\n  \"contact_name\": \"John Smith\",\n  \"contact_email\": \"john@digikey.com\",\n  \"contact_phone\": \"+1-555-0123\",\n  \"website_url\": \"https://www.digikey.com\",\n  \"payment_methods\": [\n    \"Credit Card\",\n    \"Wire Transfer\",\n    \"Purchase Order (Net 30)\"\n  ],\n  \"lead_time_days\": 2,\n  \"notes\": \"Primary supplier for ICs. Account manager: John Smith\"\n}\n```\n\n## Available Parts/Materials\n\nEach vendor maintains a catalog of materials they stock or can source.\n\n### Vendor Inventory Entry\n```rust\npub struct VendorInventoryItem {\n    pub vendor_inv_id: String,          // PK: VI-0000001\n    pub vendor_id: String,              // FK to vendors\n    pub sku: Option<String>,            // FK to our inventory (null if not in our system yet)\n    pub vendor_part_number: String,     // Their part number\n    pub description: String,            // As listed by vendor\n    pub current_price: Option<f64>,     // Current price\n    pub currency: String,               // \"USD\", \"EUR\", etc.\n    pub minimum_order_qty: i32,         // MOQ\n    pub lead_time_days: Option<i32>,    // Days to delivery\n    pub stock_level: Option<String>,    // \"In stock\", \"2-3 weeks\", \"Discontinued\"\n    pub last_checked: DateTime,         // When price/availability verified\n    pub is_available: bool,             // Currently available\n}\n```\n\n### Usage Workflow\n\n**Scenario 1: You're sourcing a new component**\n1. Search vendor catalogs for \"1M resistor\"\n2. Find `DIGIKEY-1234567` in Digi-Key inventory\n3. Record in `vendor_inventory`: part number, price, MOQ, lead time\n4. When you order and receive it, create inventory entry with internal SKU `0000001`\n5. Link vendor item to your SKU\n\n**Scenario 2: You already have a component in inventory**\n1. Have `0000001` (1M resistor) in internal inventory\n2. Find same part at 3 different vendors\n3. Add 3 vendor inventory entries, each linked to your SKU\n4. Compare prices and lead times\n5. Choose best vendor for next order\n\n## Historical Pricing\n\nTrack price changes over time for cost analysis and trend detection.\n\n### Price History Entry\n```rust\npub struct PriceHistoryEntry {\n    pub price_id: String,\n    pub vendor_inv_id: String,          // Which vendor/part combination\n    pub price: f64,\n    pub currency: String,\n    pub effective_date: DateTime,\n    pub notes: Option<String>,          // \"Bulk discount applied\", etc.\n}\n```\n\n### Example\n```\nDigi-Key - 1M Resistor (MFR-1234567)\n\nDate         Price    Notes\n2025-01-15   $0.05    Standard price\n2025-02-01   $0.048   Volume discount (100+)\n2025-02-15   $0.045   Price reduction\n2025-03-01   $0.047   Slight increase\n```\n\n### Queries Enabled\n- \"What's the price trend for this component?\"\n- \"Which vendor had the best price 6 months ago?\"\n- \"When did prices drop for component X?\"\n- \"Average price per vendor across all parts?\"\n\n## Previous Order References\n\nComplete purchase order history for audit trail and future reference.\n\n### Purchase Order Structure\n```rust\npub struct PurchaseOrder {\n    pub po_id: String,                  // Internal ID: PO-0000001\n    pub vendor_id: String,              // Which vendor\n    pub po_number: String,              // Vendor's PO number\n    pub order_date: DateTime,\n    pub expected_delivery: DateTime,\n    pub actual_delivery: Option<DateTime>,\n    pub total_amount: f64,\n    pub currency: String,\n    pub status: PurchaseOrderStatus,    // Draft, Submitted, Shipped, Delivered, etc.\n    pub notes: String,\n}\n\npub struct PurchaseOrderLineItem {\n    pub po_line_id: String,\n    pub po_id: String,\n    pub vendor_inv_id: String,          // Reference to what we ordered\n    pub sku: Option<String>,            // What we received (FK to inventory)\n    pub quantity: i32,\n    pub unit_price: f64,\n    pub line_total: f64,\n}\n```\n\n### Example Order\n```\nPO #: PO-0000001\nVendor: Digi-Key (V001)\nVendor PO#: DK-2025-123456\nOrder Date: 2025-03-01\nExpected Delivery: 2025-03-03\nActual Delivery: 2025-03-03\nStatus: Delivered\nTotal: $1,234.56 USD\n\nLine Items:\n1. Enter company name (required)\n2. Add contact person, email, phone (optional)\n3. Add website URL\n4. Select payment methods accepted\n5. Estimate typical lead time\n6. Save vendor profile → generates vendor_id (V-0000001)\n\n### Add Vendor Material\n1. Select vendor from list\n2. Enter vendor's part number\n3. Enter description (auto-search if possible)\n4. Enter current price and MOQ\n5. Enter lead time\n6. Mark availability\n7. Link to internal SKU (if item already in inventory)\n8. Save → generates vendor_inv_id\n\n### Record Purchase Order\n1. Select vendor\n2. Enter vendor PO number\n3. Add line items (select from vendor materials or add new)\n4. For each item: quantity, unit price, internal SKU (after receiving)\n5. Set expected delivery date\n6. Submit → creates audit trail\n7. Update status when shipped/delivered\n8. Receive items → create/update inventory entries\n\n### Update Pricing\n- Automatically record current price when updating vendor material\n- Historical entry created automatically\n- Can manually add historical prices for records\n\n## Data Flow: Sourcing a New Component\n\n```\n1. Need: 1M Resistors\n   ↓\n2. Search vendor catalogs\n   ├─ Digi-Key: DK-1234567 @ $0.05 each\n   ├─ Mouser: MOU-9876543 @ $0.048 each\n   └─ Local: LOCAL-5555 @ $0.08 each\n   ↓\n3. Record 3 vendor items (not yet in our system)\n   ├─ vendor_inv_id: VI-0000001 (Digi-Key)\n   ├─ vendor_inv_id: VI-0000002 (Mouser)\n   └─ vendor_inv_id: VI-0000003 (Local)\n   ↓\n4. Create purchase order to Mouser (best price)\n   └─ PO-0000001: 1000 units @ $0.048 = $48.00\n   ↓\n5. Receive shipment\n   ├─ Create inventory item: name, description, qty 1000\n   ├─ Backend generates SKU: 0000001\n   └─ Link PO line item to SKU 0000001\n   ↓\n6. Component now in system\n   ├─ SKU 0000001 = 1M Resistor\n   ├─ Available from 3 vendors at different prices\n   ├─ Full purchase history tracked\n   ├─ Price trends visible\n   └─ Ready for orders/BoMs\n```\n\n## Reporting\n\n### Vendor Performance\n- On-time delivery rate\n- Average lead time\n- Price stability\n- Order accuracy\n\n### Cost Analysis\n- Price trends per vendor\n- Best supplier per component\n- Volume discounts available\n- Cost savings opportunities\n\n### Supplier Management\n- Vendor contact info at a glance\n- Payment methods reminder\n- Next order due date suggestions\n- Supplier relationship notes\n"
