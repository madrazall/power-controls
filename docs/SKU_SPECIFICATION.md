# SKU Generation Specification (Revised)\n\n## Format Definition\n\n```\n[7-DIGIT-NUMBER]\n└─────┬─────┘\n   Sequence\n```\n\n### Components\n\n#### Seven-Digit Number\n- **Format:** Zero-padded decimal\n- **Range:** 0000001 through 9999999\n- **Assignment:** Sequential, globally unique (not per-category)\n- **Reuse:** Never - retired items keep their SKUs permanently\n- **No special characters:** Digits only\n\n## SKU Generation Algorithm\n\n```rust\nfn generate_sku() -> Result<String, Error> {\n    // 1. Query database for highest sequence number ever assigned\n    let last_sequence = db.get_max_sequence()?;\n    \n    // 2. Increment sequence\n    let new_sequence = last_sequence + 1;\n    \n    // 3. Check overflow (7-digit limit)\n    if new_sequence > 9_999_999 {\n        return Err(\"SKU pool exhausted - 9,999,999 items max\");\n    }\n    \n    // 4. Format: 0000001\n    let sku = format!(\"{:07}\", new_sequence);\n    \n    // 5. Return SKU\n    Ok(sku)\n}\n```\n\n## Examples\n\n✓ **Valid SKUs:**\n- `0000001` - First inventory item added\n- `0000042` - 42nd item\n- `9999999` - Last possible item\n\n✗ **Invalid SKUs:**\n- `000001` - Only 6 digits\n- `00000001` - 8 digits\n- `1` - Not zero-padded\n- `PC-0000001` - Contains non-digit characters\n- `0000000` - Sequence starts at 1, not 0\n\n## Uniqueness Constraints\n\n### Database Schema\n\n```sql\nCREATE TABLE inventory (\n    sku TEXT PRIMARY KEY,              -- 0000001 (unique, immutable)\n    name TEXT NOT NULL,                -- \"1MΩ Carbon Film\"\n    description TEXT,                  -- Detailed specs\n    category TEXT,                     -- \"Resistor\" (optional, for filtering)\n    status TEXT DEFAULT 'active',      -- 'active', 'obsolete', 'discontinued'\n    quantity_on_hand INTEGER DEFAULT 0,\n    reorder_point INTEGER DEFAULT 0,\n    location TEXT,                     -- Storage bin/location\n    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,\n    retired_at TIMESTAMP\n);\n\nCREATE TABLE sku_sequence (\n    id INTEGER PRIMARY KEY,            -- Always 1 (single row)\n    next_sku INTEGER NOT NULL          -- 1 (next to assign)\n);\n\nCREATE INDEX idx_inventory_category ON inventory(category);\n```\n\n## Assignment Strategy\n\n### Adding New Inventory Item (Physical Stock Present)\n\n1. **User submits:** Component name, description, category (optional)\n2. **Backend validation:** Check item doesn't already exist\n3. **Generate SKU:**\n   - Lock `sku_sequence` row for atomic read/update\n   - Read `next_sku` value (e.g., 42)\n   - Increment to 43\n   - Update database\n   - Unlock\n4. **Insert inventory:** SKU `0000042` + component data\n5. **Return** SKU to user\n\n### No Manufacturer/External Part Numbers Required\n\n- Manufacturer part numbers are **reference only**\n- Stored in separate `external_part_references` table\n- Not required to add item to inventory\n- Can be added/updated any time\n\n## Migration Path for Existing Inventory\n\nIf importing existing components:\n1. Disable SKU auto-increment temporarily\n2. Sort existing items chronologically\n3. Assign sequential 0000001, 0000002, etc. in order\n4. Create audit log mapping: `old_reference` → `new_sku`\n5. Re-enable auto-increment at highest+1\n\n## SKU Retirement Process\n\nWhen a component is no longer stocked:\n1. Mark as `status = 'discontinued'` or `'obsolete'`\n2. **DO NOT** reuse the SKU\n3. Keep complete history (audit trail)\n4. If item is restocked, restore status to `'active'`\n5. SKU remains permanent\n\n## Concurrency & WAL Mode\n\n- SQLite operates in WAL (Write-Ahead Logging) mode\n- Multiple users can read while one writes\n- `sku_sequence` single row prevents collision\n- Atomic transaction ensures no duplicate SKUs\n\n## Performance\n\n- **Sequence lookup:** O(1) - single row, primary key\n- **SKU generation:** < 10ms typical\n- **Inventory insert:** < 100ms (including SKU generation)\n- **Category query:** O(log N) with index\n\n## Future Scalability\n\n- Current format supports up to 9,999,999 items\n- If more capacity needed, extend to 8+ digits\n- No prefix system means no category expansion limits\n"
